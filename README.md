# server-audit v3.3.0

Универсальная диагностика Linux-сервера для технической поддержки. Один
Bash-скрипт без установки обязательных зависимостей: определяет доступный стек, собирает
состояние, историю инцидентов и факты для разбора инженером или нейросетью.
Проверки в первую очередь диагностические, **не исправляют сервер автоматически**.

## Быстрый запуск

На сервере от root:

```bash
curl -fsSL https://raw.githubusercontent.com/lyfreedomitsme/server-audit/main/server_audit.sh | bash
```

Если вы уже знаете проблемный домен, приоритетно проверяйте его:

```bash
curl -fsSL https://raw.githubusercontent.com/lyfreedomitsme/server-audit/main/server_audit.sh | AUDIT_DOMAIN=example.com PASTE=0 bash
```

Можно сначала скачать и прочитать код:

```bash
curl -fsSL https://raw.githubusercontent.com/lyfreedomitsme/server-audit/main/server_audit.sh -o server_audit.sh
sudo bash server_audit.sh
```

Прогресс выводится в stderr, итоговый текстовый отчёт — в stdout. Чтобы
сохранить отчёт **на своём компьютере**, а не на клиентском сервере, из
локального терминала:

```bash
ssh root@SERVER_IP 'curl -fsSL https://raw.githubusercontent.com/lyfreedomitsme/server-audit/main/server_audit.sh | PASTE=0 bash' > report.txt
```

Передавайте этот отчёт инженеру или в чат целиком. Перед передачей проверьте
его на чувствительные данные. Повторный запуск после восстановления даёт
второй снимок состояния, но скрипт не сохраняет первый снимок сам.

## Что собирает отчёт

### Инциденты и изменения

- Дата UTC, uptime, boot ID, история загрузок и завершений работы (`last -x`,
  `journalctl --list-boots`).
- Журнал текущей и предыдущей доступной загрузки за заданный интервал:
  ошибки ядра, OOM, segfault, ошибки I/O. Журнал событий сервисов: start/stop,
  restart, ошибки, остаточные процессы. Для основных веб-серверов, PHP и БД
  отдельно показан недавний журнал каждого сервиса.
- Установленные и остановленные systemd-юниты, `ActiveState`, `SubState`,
  `Result`, `is-enabled`, память, лимиты, число перезапусков и временные
  метки. Для SysV — ссылки S/K и их mtime. Отличает работающий сейчас, но
  отключённый в автозапуске сервис от отсутствующего сервиса.
- Последние OOM-события с именами реальных жертв и контекстом таблицы задач
  ядра. Убитый OOM-процесс не обязательно был главным потребителем памяти.
- Ограниченные выдержки из истории root **только** для распознаваемых
  команд start/stop/restart/enable/disable/mask и update-rc.d. Не выводит
  весь shell history или параметры произвольных команд.
- Для aaPanel — признаки установки веб-серверов из installer logs и
  операции управления сервисами из request logs (без целых JSON-запросов,
  IP и cookies). Mtime конфигураций — дополнительное свидетельство, не
  доказательство авторства или причины изменения.
- Список сохранённых файлов atop/sysstat для последующего точечного анализа.
  Если история журналов не сохранена, скрипт сообщает о недоступности;
  восстановить удалённые события он не может.

### Панели, обновления и действующие firewall-правила

- Отдельный ранний блок для FASTPANEL, HestiaCP, ISPmanager, DirectAdmin,
  aaPanel/BT, VestaCP, Plesk, cPanel/WHM, CyberPanel, CloudPanel,
  Webmin/Virtualmin и KeyHelp. Типичные порты — подсказка; учитываются
  найденные слушатели процессов, а для HestiaCP, DirectAdmin, aaPanel и
  Webmin — известные настройки порта. Нестандартную панель/порт можно задать
  через `AUDIT_PANEL_PORT` и `AUDIT_PANEL_HOST`.
- HTTP(S) GET на локальный listener панели, с кодом, временем подключения,
  TTFB и размером ответа. Для FASTPANEL дополнительно проверяются
  `/resource/public/settings`, `/resource/menu_logo`, `/license/status`
  и реальный публичный API-маршрут backend на 5501, если этот listener есть.
  Обычный HTTP 200 корня не доказывает исправность API, а 404 не всегда ошибка.
- Раздельно проверяются ответ приложения и доверие TLS; печатаются
  метаданные реально отдаваемого публичного сертификата, без ключей.
  При заданном имени панели (или обнаруженном FASTPANEL vhost) проверяются
  DNS и Host/SNI. Локальная проверка не доказывает доступность извне.
  Локальные пробы не передают пароли, cookies и не переходят по редиректам.
- Приоритетные выдержки из ошибок панели, backend и updater (включая
  timeout, ошибки лицензирования и миграции). Журнал может быть историческим.
- Debian/Ubuntu: `dpkg --audit`, симуляция `apt-get -s check`,
  установленные версии и кандидаты из существующего кеша, held-пакеты,
  видимые блокировки. При нарушенных зависимостях безопасная симуляция
  `apt-get -s --no-remove --fix-broken install`; пакеты не изменяются.
  RPM: инвентарь и проверка зависимостей в доступном кеше.
- UFW: сравнение простых разрешающих TCP/UDP правил в сохранённых файлах
  с реально загруженными цепочками IPv4 и IPv6. `FIREWALL DRIFT` показывает
  конкретное недостающее или дополнительное правило, даже если
  `ufw status` выглядит нормально. Для firewalld — активные зоны и
  runtime/permanent порты и сервисы; для iptables/nftables — политики
  INPUT и выборочные правила портов найденных панелей.
- Сравнение не заменяет вычисление полного маршрута пакета: правила с
  условиями, ranges/sets, порядок цепочек и внешние firewall провайдера
  могут повлиять на доступность. Ничего не открывает и не перезагружает.

Пример для панели на нестандартном порту:

```bash
curl -fsSL https://raw.githubusercontent.com/lyfreedomitsme/server-audit/main/server_audit.sh | AUDIT_PANEL_HOST=panel.example.com AUDIT_PANEL_PORT=9443 PASTE=0 bash
```

### Веб-серверы и 502/503/504

- Инвентаризация всех обнаруженных DNS-имён из известных конфигураций
  Nginx, Apache, LiteSpeed/OpenLiteSpeed: основные virtual hosts, алиасы,
  исключение wildcard, IP-литералов и служебных placeholder. Сначала
  приоритетный AUDIT_DOMAIN, затем основные имена, потом алиасы.
  Список не доказывает, что vhost активен или DNS настроен.
- Для выбранных имён выводятся HTTP-коды, задержки и категории результата:
  2xx (ответ получен), 3xx (редирект без перехода), 401/403 (доступ
  ограничен), 404, другие 4xx, 5xx, таймаут, ошибки подключения/DNS/TLS,
  отсутствие локального listener/backend. Непроверенные имена явно
  отмечены NOT CHECKED. По умолчанию до 30 имён и бюджет 120 секунд,
  проверяемый между сайтами; в ходе последнего сайта бюджет может быть
  превышен на время его отдельных запросов. HTTP 200 не доказывает
  исправность всех функций приложения.

- Nginx, Apache/httpd, LiteSpeed/OpenLiteSpeed: обнаружение системных
  бинарников и типичных установок панели вне PATH (включая aaPanel).
- HTTP/TCP/Unix-слушатели с именами владельцев процессов.
- `nginx -t/-T`, `apachectl -t/-S`, версии, vhost и выборочные директивы.
  Полные конфиги не печатаются. OLS: listener, map, адреса и метаданные
  конфигов, выборочные PHP-обработчики.
- Сравнение статических upstream (proxy_pass, FastCGI, локальные сокеты)
  с реальными слушателями. Например, Nginx направляет запросы на 8290,
  Apache не запущен, OpenLiteSpeed слушает 8190: отсутствие listener на
  8290 будет выделено. Именованные/динамические/удалённые upstream не
  объявляются сломанными только потому, что нельзя проверить их локально.
- Локальные GET-запросы к фронту 80/443 и найденным статическим loopback
  HTTP(S)-бэкендам с корректным Host/SNI. Без перехода по редиректам и
  без сохранения тела. Для проверки локальной маршрутизации TLS отключена
  проверка сертификата; если фронт слушает конкретный локальный адрес, используется
  доступный адрес listener. Внешний HTTPS-тест указанного домена проверяет
  сертификат штатно; AUDIT_PUBLIC_HTTP=1 добавляет внешние HTTPS-пробы
  для всех выбранных имён (если разрешён SKIP_NET=0). GET может попасть в access-log или запустить
  прикладную логику: `SKIP_HTTP=1` отключает эти пробы.
- Ошибки Nginx/Apache/OLS/PHP/MariaDB: connection refused, upstream
  timeout, SSL handshake, fatal error, PHP startup, max_children. Логи
  берутся ограниченными хвостами, включая некоторые ротации `.1`.
- PHP-FPM разных версий: сокеты, pm, max_children, размеры пулов, настройки
  памяти, лог ошибок и startup warnings. Поддерживаются типичные layout
  Debian/Ubuntu, RHEL, aaPanel, Remi, Plesk, cPanel.
- Настройки MPM Apache и лимиты памяти/соединений MySQL/MariaDB.
- DNS A-записей (ограниченное число имён), сравнение с внешним IP:
  CDN/Cloudflare и прокси могут объяснять несовпадение.

### Боты и нагрузка по access-логам

Для известных путей Nginx/Apache/OLS и панелей скрипт разбирает выборку
последних строк common/combined access logs:

- Топ 10 IP по запросам и число 499/5xx по каждому IP.
- Сколько запросов обработалось, статусы HTTP, временные границы выборки
  и пиковое число запросов за минуту **в пределах выборки**.
- Классы User-Agent: поисковые роботы (непроверенная заявленная
  идентичность), crawler/bot, автоматизация/сканеры, пустой UA.
- Запросы к XML-RPC, wp-login, wp-json (включая rest_route), wp-admin,
  чувствительным путям (.env, .git, phpMyAdmin и т.п.).
- Наличие директив Nginx limit_req/limit_conn и время изменения
  aaPanel badbots-конфигурации, если они найдены.

Скрипт не блокирует IP, не выключает XML-RPC, не меняет правила firewall.
Один IP может принадлежать CDN, User-Agent подделывается, а REST API и
поисковые роботы могут использоваться легитимно. Выборка не доказывает
DDoS или взлом. Нестандартный формат логов может быть не разобран —
отчёт показывает число нераспознанных строк.

### Панели управления

| Панель | Обнаружение, известные пути, статус/логи |
|---|---|
| aaPanel / BT Panel | Расширенная диагностика Nginx, Apache, OLS, PHP, БД, vhost, история действий |
| HestiaCP / VestaCP | Статус панели, логи панели и типовые domain logs |
| ISPmanager / FASTPANEL | Статус панели, логи, типовые httpd-logs/data/logs |
| Plesk | Статус, панельные логи, vhosts/system, PHP |
| cPanel / WHM | Статус, логи панели, Apache/domlogs, EA-PHP |
| DirectAdmin | Статус, логи, domain logs |
| CyberPanel | Определение панели, lscpd и OLS |
| CloudPanel | Определение панели, Nginx и известные логи |
| Webmin / Virtualmin, KeyHelp | Определение, статус и известные логи |

Это **best effort**, а не гарантия поддержки всех версий и кастомных
раскладок. Универсальные проверки systemd, сокетов, процессов и журналов
работают независимо от панели. Скрипт не устанавливает отсутствующие панели.

### Остальной аудит сохранён

- ОС, CPU, нагрузка, RAM, доступная память, pressure stall information,
  ресурсы по именам процессов (сумма RSS может повторно учитывать общую
  память). Наблюдение SWAP — только чтение, **никогда не создаёт и не включает SWAP**.
- Диск, inode, LVM; при высокой занятости автоматический ограниченный
  по времени `du -xhd1` для основных каталогов, включая кеш Nginx.
- Сеть, IPv4/IPv6, DNS, маршруты, соседи, MTU, firewall, SSH, fail2ban.
- MySQL/MariaDB, Redis, PostgreSQL, MongoDB, PM2, Docker (включая
  unhealthy/restarting), WireGuard, сертификаты, расписание cron.
- Без systemd — доступные альтернативы OpenRC/SysV, процессы и обычные
  лог-файлы; журнал предыдущей загрузки может отсутствовать.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| AUDIT_DOMAIN | авто | Приоритетный hostname без схемы, пути или порта |
| AUDIT_PANEL_HOST | авто | Host/SNI панели для локальной проверки TLS и DNS; не адрес обычного сайта |
| AUDIT_PANEL_PORT | авто | Дополнительный TCP-порт панели, 1–65535 |
| AUDIT_HISTORY_DAYS | 7 | Интервал истории журналов, 1–90 дней |
| AUDIT_TIMEOUT | 12 | Таймаут отдельных новых проверок в секундах (если доступен timeout) |
| AUDIT_MAX_SITES | 30 | Лимит имён для HTTP/DNS, 1–100; инвентарь включает все обнаруженные имена |
| AUDIT_HTTP_BUDGET | 120 | Бюджет HTTP-проверок в секундах (между сайтами), 1–900 |
| AUDIT_PUBLIC_HTTP | 0 | 1: пробовать внешний HTTPS для всех выбранных имён, иначе только AUDIT_DOMAIN |
| AUDIT_MAX_FILES | 20 | Лимит файлов error logs, 1–100 |
| AUDIT_LOG_LINES | 20 | Строк ошибок на файл, 1–100 |
| AUDIT_BOT_FILES | 12 | Лимит access logs, 1–60 |
| AUDIT_BOT_LINES | 2500 | Строк access log на файл, 1–10000 |
| AUDIT_REPORT_LINES | 5000 | Итоговый лимит строк, 1–20000 |
| SKIP_NET | 0 | 1: не выполнять внешние сетевые тесты и публичную отправку |
| SKIP_HTTP | 0 | 1: не делать локальные и целевой внешний HTTP GET |
| DEEP_DISK | 0 | 1: принудительно выполнить ограниченный du, даже если диск не заполнен |
| PASTE | интерактивно | 0: не предлагать termbin; 1: явное согласие на публичную отправку |
| PASTE_MAX_BYTES | 30000 | Предельный размер текста одной публикации (4096–1048576 байт); реальный лимит Termbin не опубликован |
| PASTE_MODE | compact | compact: при превышении лимита явно предложить краткий отчёт; full: отменить загрузку слишком большого отчёта |
| PASTE_TTL | 15 | Задержка до первого удаления (1–540 сек., 0 отключает); затем проверка ссылки и до 3 попыток |

Пример расширенного аудита без внешних сетевых запросов:

```bash
AUDIT_DOMAIN=example.com AUDIT_HISTORY_DAYS=14 AUDIT_MAX_FILES=40 AUDIT_BOT_FILES=25 AUDIT_REPORT_LINES=10000 SKIP_NET=1 PASTE=0 bash server_audit.sh
```

Время выполнения зависит от числа сайтов, доступности сервисов и объёма
логов. У каждой новой проверки есть лимит по времени или объёму;
старые инструменты и большие локальные каталоги могут требовать больше
времени. Важные диагностические секции идут первыми; обрезка отчёта
отмечается явно.

## Безопасность и ограничения

- Нет перезапуска/остановки сервисов, включения/отключения автозапуска,
  редактирования конфигураций, удаления кешей, установки пакетов или
  изменения SWAP. Некоторые штатные диагностические утилиты сами могут
  писать служебные логи, HTTP GET оставляет обычный след в access logs.
- Временный отчёт создаётся в приватном каталоге с umask 077 и удаляется
  при нормальном завершении и обработанных сигналах; исходный временный
  файл удаляется сразу после успешной фильтрации (не обещаем гарантии
  при SIGKILL, аварии питания или физического стирания с SSD).
- При наличии Python 3 типовые распознанные пароли и токены заменяются
  на HMAC-SHA256 метки `[SECRET:...]` (96-битный усечённый отпечаток).
  Одинаковые распознанные значения могут быть сопоставлены внутри одного
  отчёта; ключ — случайные 256 бит, генерируется в памяти процесса и
  не передаётся в отчёт, аргументы, переменные окружения или сеть.
  Отпечатки между независимыми аудитами не сравнимы. Секреты специально
  не извлекаются из конфигураций; сравниваются найденные в исходной
  диагностике значения, без проверки корректности пароля. Форматы
  неоднозначного экранирования могут сопоставляться неточно. Cookies,
  PEM-блоки и прочие нераспознанные параметры URL маскируются без меток.
  Если Python отсутствует или HMAC-фильтр завершился ошибкой, используется
  обычное маскирование с явным уведомлением в отчёте. Это **не
  гарантирует** удаления всех нестандартных секретов. История команд
  ограничена разрешёнными шаблонами. Не выводятся полные конфиги,
  произвольные команды cron или аргументы процессов.
- Отчёт по-прежнему может содержать IP, домены, пути, логины, версии
  софта и чувствительные сообщения приложений. Настоятельно рекомендуется
  передавать локальный файл через доверенный канал.
- Опциональная публикация на termbin.com сохранена для совместимости.
  Ничего не отправляется без явного согласия (`PASTE=1` или ответ y
  в интерактивном терминале; вопрос `y/N` отображается и при `curl | bash`).
  В интерактивном режиме принимаются только y/Y (публикация), n/N или
  пустой Enter (отказ); любой другой ввод повторяет вопрос. EOF отменяет
  публикацию.
  Ссылка **публичная**, не защищена паролем; отправка через netcat
  не зашифрована. Для крупных отчётов по умолчанию формируется отдельная
  компактная версия не более PASTE_MAX_BYTES (30 000 байт): сохраняются
  заголовки всех разделов, разные типы ошибок с источником и временем,
  сводки SERVICE (состояние, автозапуск, результат и история остановок),
  HTTP_SITE (ответы фронтенда и бэкенда по каждому проверенному имени),
  TRAFFIC (счётчики и выборочные признаки ботов по файлу лога), OOM_COUNT
  (по загрузке и имени процесса), привязки виртуальных хостов и важные
  ограничения ресурсов. Приоритет получают признаки неисправностей и
  целевой домен. Дубли и подробности сокращаются, пропущенные записи,
  включая высокоприоритетные, явно отмечаются. Лимит не позволяет
  гарантировать полную сохранность доказательств на любом сервере. Перед y/N явно
  сообщается размер полного и компактного текста. Полный отчёт остаётся
  выше в терминале; для полной копии без сокращения выбирайте PASTE=0
  либо PASTE_MODE=full с подходящим PASTE_MAX_BYTES после проверки лимита.
  Если netcat поддерживает -N, используется завершение передачи по EOF.
  Если ссылка не получена, отображаются exit-код, размер и объём ответа;
  неоднозначная публикация автоматически не повторяется.
  Перед отправкой с включённым удалением проверяется HTTPS Termbin;
  IPv4-адрес назначения закрепляется для netcat и последующих HTTPS-запросов
  (без прокси). Если получить IPv4 не удалось, отчёт не отправляется.
  Это не гарантирует одинаковый внешний IP источника при NAT/прокси.
  Отдельный процесс запускается до показа ссылки и подтверждает готовность.
  Через 15 секунд (по умолчанию) он выполняет POST удаления, сохраняет
  результат deleted=true/false, затем проверяет GET без кеша; 404/410
  означает недоступность ссылки в момент проверки. POST ждёт ответа до
  60 секунд (с учётом оставшегося окна самостоятельного удаления), GET —
  до 15 секунд. При неудаче — до 3 попыток с интервалами 2/4 секунды,
  с HTTP-кодом, кодом завершения curl и сообщением транспортной ошибки. По возможности
  используется setsid (в том числе BusyBox), иначе nohup. Ctrl+C после
  показа ссылки не останавливает уже запущенный процесс в проверенных
  сценариях; это не гарантируется при остановке всей SSH-сессии
  провайдером или сервера. Дождитесь результата проверки. Есть команда
  ручного удаления с закреплённым IPv4.
  Это **не гарантия стирания данных** или отсутствия сторонних копий:
  Termbin — внешний сервис, сеть/публикация могут отказать. Для клиентских
  серверов предпочтительно `PASTE=0`. `SKIP_NET=1` запрещает публикацию.
- Анализ конфигураций эвристический: текущая on-disk конфигурация может
  отличаться от загруженной в память, а нестандартные протоколы,
  include, переменные и форматы требуют ручной проверки. Отчёт содержит
  доказательства, а не универсальную автоматическую постановку диагноза.

## Тесты

```bash
bash -n server_audit.sh
bash tests/incident.sh
bash tests/sites.sh
python3 tests/redaction.py
python3 tests/hmac.py
python3 tests/paste.py
python3 tests/paste_https.py
python3 tests/compact.py
```

Регрессионные тесты используют синтетические данные (не запускают
сервисы и не обращаются к клиентским серверам): несовпадение портов,
Unix-сокеты, выборочные конфиги, OOM предыдущей загрузки, боты и
маскирование чувствительных значений, совпадение HMAC-меток в разных
форматах, независимость ключей между запусками, безопасный fallback,
инвентаризацию и различные HTTP-ответы. Тест публикации использует
псевдотерминал и заглушки nc/curl: проверяет y/N, повтор вопроса при
ошибочном вводе, пустой Enter и EOF, отсутствие отправки
при отказе, точное содержимое отправки, ограничение размера и маркировку сокращения, EOF-флаги, NUL/CRLF в ответе, URL http/https, отсутствие ответа, задержку, HTTP 404/410,
повторные попытки, сетевые ошибки, отказ от отправки при недоступности
IPv4, одинаковый адрес назначения, JSON-результат POST и продолжение работы
дочернего процесса при Ctrl+C сразу после показа ссылки.
Тест compact.py проверяет большой синтетический отчёт: сохранность
привязки ошибок, статусов служб, HTTP-ответов, OOM и статистики трафика
при сокращении до 30 000 байт.
Интеграционный тест paste_https.py использует реальные локальные TCP/TLS-
соединения и curl: при искусственной задержке POST в 10 секунд старый
8-секундный предел вызывает curl exit=28, новый запрос дожидается
удаления и проверяет HTTP 404. Нужны также openssl и curl.
Фактическое удаление на внешнем Termbin этими тестами не подтверждается.
Для Python-тестов необходим Python 3.9+; HMAC в самом аудите использует
стандартную библиотеку Python 3, если она доступна.
